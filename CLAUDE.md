# Lunar Landing Site Navigator: project rules

This is a web app for the NASA Space Apps 2026 challenge "Lunar Landing Site Navigator". It lets **mission planners, educators and the public** compare lunar landing sites and dates in seconds. For any site and time it shows where the Sun and Earth sit relative to the **real terrain horizon** (LRO LOLA). From that it derives power windows, direct-to-Earth link windows, sunset and Earthset countdowns, and viable landing dates when a schedule slips. Deadline: Sun 2026-11-15, 23:59 local-event time.

There are two audiences in one UI. **Planner mode** shows dense numbers and comparisons. **Explore mode** adds plain-language explanations.

## Physics rules (non-negotiable)
- Sun or Earth is **visible** only when it is above the **local LOLA terrain horizon** (`site.horizon`), never above 0°.
- Disc sizes:
  - The Sun's disc is 0.533° (radius `SUN_RADIUS_DEG` = 0.2666°).
  - Earth's disc is about 1.9°; its radius is computed from the live Earth–Moon distance: `asin(6371 / d)`.
  - Report partial visibility as the **% of disc area above the horizon**, using the circular-segment formula `discFractionAbove()`.
- **Sunrise and sunset happen when the upper limb crosses the terrain horizon** (`margin + radius = 0`). Earthrise and Earthset use the same rule.
- Distant terrain: horizon masks use **exact spherical 3D geometry** (`pipeline/horizon_mask.py`, `web/src/lib/terrain.ts`). To first order this equals the curvature drop `d²/2R` with R = 1737.4 km, and a unit test asserts the agreement (`curvatureDropKm`).
- No atmospheric refraction.
- **Longitude:**
  - Stored internally (data files, `Site.lon`) as **east-positive 0–360°**.
  - Normalize every input with `normalizeLon360()`.
  - Display as −180..180 with E/W labels (`formatLon()`).
- **Time:** stored as UTC (ISO 8601 strings, epoch ms in memory). The UI shows UTC by default, with a local-time toggle.
- The Earth position includes **libration**. It comes from JPL Horizons sub-observer points (MOON_ME frame), never from a fixed point.
- Every curated site needs a `source` citation. Unverified coordinates set `verify: true`, which shows a badge.

## Data contract (`web/public/data/`, generated by `pipeline/`)
- `ephem.json` + `ephem.bin`:
  - The `.bin` is Float32 LE with rows × 6: `[earth_x_km, earth_y_km, earth_z_km, sun_x, sun_y, sun_z]`, in the MOON_ME frame.
  - Rows are hourly from `startMs`; `count` gives the number of rows.
  - The meta also holds `stepMs`, `moonRadiusKm`, `earthRadiusKm` and `source`.
- `sites.json`:
  - Top level: `{ azStepDeg, maxDistanceKm, observerHeightM, terrain, sites: Site[] }`.
  - `Site = { id, name, group, lat (−90..90), lon (0..360 E), source, verify, elevationM, horizon: number[360/azStepDeg] }`.
  - `horizon[i]` is the terrain elevation angle (°) at azimuth `i·azStepDeg`, measured clockwise from north, for an observer `observerHeightM` above the surface.
- Browser terrain:
  - `dem_polar.json/.bin` is Int16 LE in metres above the 1737.4 km sphere. It uses a south polar stereographic grid `n×n`, `scaleM` per pixel, centre `offsetPx`, and covers lat ≤ `minLat`.
  - `dem_global.json/.bin` is Int16 LE, simple cylindrical, `ppd` pixels per degree, row 0 at 90° N, column 0 at 0° E.
- `pgda_sun.bin`, `pgda_earth.bin`: Uint8 on the polar grid. Values are % of time visible; 255 means no data.
- `validation.json`: `{ period, worstElevationErrorDeg, sites[], illumination{}, missions[] }`.
- In-app time series: `Sample` in `web/src/lib/analysis.ts`. It has az/el, terrain horizon, margin and disc fraction for both the Sun and Earth, at the time `t` (ms UTC).

## Code conventions
- TypeScript strict. No `any` in physics code (`web/src/lib/physics/*`, `geometry.ts`, `analysis.ts`, `terrain.ts`).
- Physics lives in **pure functions**, separate from React components. Components never compute geometry inline.
- **Every physics function has a unit test** (`web/src/lib/**/*.test.ts`, Vitest).
- Styling uses only the design tokens in `web/src/styles/tokens.css`. No hard-coded colours in components, SVG or canvas; read them with `cssVar()`.
- User-facing text is in English and sentence case. Every number carries its unit.
- No NASA logos or insignia anywhere. Any AI-generated media needs a visible watermark.
- Log every AI-assisted task in `docs/AI_USAGE.md` (date, task, files).

## Definition of done (every change)
1. `npm run build` passes, with 0 TypeScript errors and 0 lint errors (`npm run lint`).
2. `npm test` (unit) and `python tests/e2e/smoke_test.py` (Playwright) pass.
3. There are no console errors or warnings on any screen.
4. Screenshots are taken (`tests/e2e/screenshots.py`) and checked against the design system.
5. `docs/AI_USAGE.md` is updated and the work is committed.
